8.1 Stable knee, hip and elbow angles

A joint angle is the angle at point B between segments BA and BC. Ullah et al. compute it with the cosine rule from three keypoints [4]; the dot-product form below is the same thing:

θ = arccos( (A−B)·(C−B) / (|A−B| |C−B|) ) 
def joint_angle(a, b, c):
    v1, v2 = a - b, c - b
    cos = np.sum(v1*v2, axis=1) / (np.linalg.norm(v1, axis=1) * np.linalg.norm(v2, axis=1))
    return np.degrees(np.arccos(np.clip(cos, -1, 1)))

Common triplets: knee = hip–knee–ankle (squat, lunge), hip = shoulder–hip–knee (hinge, deadlift), elbow = shoulder–elbow–wrist (push-up, curl). Two design decisions:

  • Filter positions, then compute angles (what we do), or compute angles, then filter the angle. Filtering positions keeps the skeleton drawable and lets confidence gating work per joint; filtering the angle is cheaper (one filter instead of six) and its parameters are in degrees, which are easier to reason about. Both work; do not do both with heavy settings or the lag adds up.
  • Near 180° the angle is less sensitive. arccos flattens near a straight leg, so jitter on a nearly straight knee looks smaller in degrees than the same jitter at 90°. Thresholds near full extension (e.g. "lockout") need more margin.

From the angle series, Ullah et al. derive range of motion (max − min angle), angular velocity, and per-repetition similarity to a reference using dynamic time warping and normalized cross-correlation, reporting joint-angle errors of about 1.6–3.2% against clinician measurements [4]. Every one of those quantities depends on how clean the angle is.

8.2 Rep counting

A rep is a cycle: the angle goes down past a "bottom" level and comes back up past a "top" level. The simplest counter uses one threshold and counts each upward crossing. With noise near that threshold, a single real crossing can produce several.

Results on our 10-rep simulated sequence (Section 9):

SignalSingle threshold (130°)Hysteresis (115° / 160°)
Raw12 ✗10 ✓
Moving average (N = 7)10 ✓9 ✗
EMA, One Euro, Kalman10 ✓10 ✓

Two lessons. First, either filtering or hysteresis alone fixed the double counts on the raw signal; use both. Second, too much smoothing can cause the opposite error: the moving average's attenuated bottom (Section 7.3) did not get below 115° on one fast rep, so a real rep was missed. Thresholds and filter strength must be chosen together.

8.3 Phase detection

Many form rules only apply in one phase ("knees caving in on the way up", "pause at the bottom"). Phases come from the sign of angular velocity ω = dθ/dt:

  • Descent: ω < −ω0   Ascent: ω > +ω0   Bottom / Top: |ω| ≤ ω0, split by whether θ is below or above the midpoint.

The dead band ω0 (e.g. 20–30°/s) plays the same role as rep-counter hysteresis. As Section 1.3 showed, raw angular velocity can have about 70°/s of noise, so on the raw signal the phase label would flip almost every frame. Velocity must come from a filtered angle, from the One Euro filter's internal dx̂, or from the Kalman velocity state (which is a nice side benefit of the Kalman filter: it estimates velocity for free).

8.4 Reducing false form-error alerts

Form feedback that fires on noise trains users to ignore it; the review by Tharatipyakul et al. identifies managing erroneous feedback as an open problem [1]. Filtering is the first defense. Three more patterns help:

  1. Persistence (debouncing). Only report a form error if it holds for k consecutive valid frames (e.g. 5 frames ≈ 170 ms). A one-frame spike can never trigger it.
  2. Margins. Warn at "knee angle < 70°" only if the angle is below 70° minus a margin about two times the remaining jitter.
  3. Per-rep decisions. Evaluate depth, tempo and symmetry once per rep (from the rep's whole angle curve) rather than every frame. This allows non-causal smoothing inside each completed rep at the cost of feedback arriving when the rep ends, which is how Ullah et al.'s DTW-based scoring works [4].

8.5 Putting it together

# one per landmark per coordinate
filters = {(j, d): Kalman1D(q=10, r=1e-4) for j in JOINTS for d in "xy"}
smooth  = {(j, d): OneEuro(1.0, 15.0)     for j in JOINTS for d in "xy"}
counter, bad_frames = RepCounter(down=115, up=160), 0

for frame, t in camera:
    lms = detector.detect_for_video(frame, t)            # raw x, y, visibility
    pts, valid = {}, True
    for j in JOINTS:
        lm = lms[j] if lms else None
        z  = (lm.x, lm.y) if lm else (None, None)
        c  = lm.visibility if lm else 0.0
        p  = [filters[j, d].filter(z[i], t, confidence=c) for i, d in enumerate("xy")]
        p  = [smooth[j, d].filter(p[i], t) for i, d in enumerate("xy")]
        pts[j] = np.array(p)
        valid &= filters[j, "x"].P[0, 0] < MAX_VAR        # joint lost?
    if not valid or not bone_ok(pts["hip"], pts["knee"], pts["ankle"], *ref):
        continue                                         # skip analytics this frame
    angle = joint_angle(pts["hip"], pts["knee"], pts["ankle"])
    counter.update(angle)
    bad_frames = bad_frames + 1 if angle < MIN_SAFE - MARGIN else 0
    if bad_frames == 5: say("Control the depth")

This is pseudocode (helper classes like RepCounter are left out) but every piece corresponds to a section of this tutorial: Kalman for gating, gaps and outliers (5, 6), One Euro for final smoothness (4), validity checks (6.4), angle (8.1), hysteresis counter (8.2) and persistence for alerts (8.4).

Summary

  • Stable keypoints → stable angles → reliable ROM, velocity and similarity scores.
  • Use hysteresis for reps and dead bands for phases; tune them with the filter, not separately.
  • Debounce form alerts and skip frames with invalid joints.
