5.1 State vectors

The Kalman filter, introduced by R. E. Kalman in 1960 [7], estimates a hidden state from noisy measurements using a linear model of how the state changes. Welch and Bishop's introduction is the standard practical reference for the equations below [8].

For one keypoint coordinate we use a two-element state, position and velocity:

sk = [ pk , vk ]T,    with covariance Pk (2×2) describing how unsure we are about each

Other common choices are a 4-element state [x, y, vx, vy] per joint (equivalent to two independent filters if x and y noise are independent), a 3-element constant-acceleration state [p, v, a], or one large state for the whole skeleton. We keep it per-coordinate so it plugs into the same pipeline as the One Euro filter.

5.2 Prediction and measurement updates

Predict. Move the state forward one time step with the motion model F, and increase the covariance by the process noise Q, which says "the body may have accelerated in a way the model did not expect."

Update. The detector gives a measurement z of position only, so H = [1 0]. The innovation y = z − Hs⁻ is how surprised we are. Its expected variance is S = HP⁻Hᵀ + R. The Kalman gain K = P⁻Hᵀ/S decides how far to move toward the measurement: if the prediction is uncertain (P⁻ large) relative to the measurement noise R, K is close to 1 and we trust the detector; if the detector is noisy relative to the prediction, K is small and we trust the model. Because K also has a velocity component, every measurement also corrects the velocity estimate.

5.3 Position/velocity motion models

The constant-velocity (CV) model assumes the velocity changes only through random acceleration with variance q:

F = [ 1 Δt ; 0 1 ],    Q = q · [ Δt⁴/4 Δt³/2 ; Δt³/2 Δt² ],    H = [ 1 0 ],    R = r 
class Kalman1D:
    def __init__(self, q=10.0, r=1e-4):
        self.q, self.r, self.s, self.P = q, r, None, None

    def predict(self, t):
        dt = t - self.t_prev
        F = np.array([[1, dt], [0, 1]])
        Q = self.q * np.array([[dt**4/4, dt**3/2], [dt**3/2, dt**2]])
        self.s, self.P, self.t_prev = F @ self.s, F @ self.P @ F.T + Q, t

    def update(self, z, r_scale=1.0, gate=16.0):
        H = np.array([[1.0, 0.0]])
        y = z - (H @ self.s)[0]                      # innovation
        S = (H @ self.P @ H.T)[0, 0] + self.r * r_scale
        if y * y / S > gate:                         # > 4 sigma: outlier
            return False
        K = (self.P @ H.T) / S
        self.s = self.s + K[:, 0] * y
        self.P = (np.eye(2) - K @ H) @ self.P
        return True

The full version, with initialization and confidence handling, is in experiment/filters.py; a matrix-free JavaScript version is in js/filters.js.

Choosing r and q. r is the detector's position noise variance. You can measure it directly: record someone standing still and take the variance of a keypoint coordinate (our simulated jitter of σ ≈ 0.0045 gives r ≈ 2×10⁻⁵; we used 10⁻⁴ to also absorb slow drift). q sets how quickly the filter believes velocity can change. Large q → fast response but more jitter; small q → smooth but overshoots at direction changes. For human limbs in normalized coordinates, q between about 5 and 60 worked in our tests, and q = 10 was a good balance.

Other models. A constant-acceleration model adds a third state and follows curved motions better, but its extra derivative makes it noisier. For repetitive exercises you could even use a periodic model, but that breaks as soon as the person pauses. An offline Rauch–Tung–Striebel smoother runs the Kalman filter forward and then backward through a recorded clip, giving zero-lag results like the Gaussian filter in Section 3.

5.4 Handling noisy observations

The Kalman filter has three built-in ways to deal with bad measurements, all used in our experiment:

  1. Confidence-scaled noise: Rk = r / ck². A keypoint with visibility 0.6 is trusted about 2.8× less than one with 1.0.
  2. Skip the update when the keypoint is missing or ck < 0.5. The prediction alone carries the estimate forward (Section 6).
  3. Innovation gating: if y²/S > 16 (more than 4 standard deviations from the prediction), treat the measurement as an outlier. This removes single-frame spikes and many left/right swaps, which simple low-pass filters cannot do.
Gating can lock out real motionIf the person really does move suddenly, the measurement may be rejected several frames in a row while P keeps growing. Because S grows with P, the gate eventually opens again, but there can be a short delay. Counting consecutive rejections and resetting the filter after a few is a common safeguard.

Numbers come from the experiment in Section 9. A practical pattern is to use both: a Kalman filter (or just its gating and gap prediction) to clean outliers and fill gaps, followed by a One Euro filter for display-quality smoothness.

Summary

  • State = [position, velocity]; predict with F and Q, correct with K.
  • q controls responsiveness, r the trust in the detector; measure r from a still recording.
  • Confidence-scaled R, skipped updates and innovation gating make it robust to bad keypoints.
  • Kalman wins on lag, gaps and outliers; One Euro wins on smoothness at rest and simplicity.
